# Update Memory

Use after meaningful repo work to persist knowledge for future sessions.

## Update `memory/active.md`

- Move completed items to "Recently Completed" (keep last ~5)
- Add new WIP items with since-date and why
- Update blocked items
- Add/resolve pending decisions

## Update data files (if new learnings)

- `memory/architecture.md` — new pattern applied or decision made
- `memory/spec-knowledge.md` — new format fact or spec detail learned
- `memory/gotchas.md` — new pitfall encountered
- `memory/research.md` — new research finding

## Update root files (if project state changed)

- `MEMORY.md` — open questions, priorities, design direction
- `INDEX.md` — if new files or navigation paths added

## Clear ephemeral state

- Clean `memory/scratchpad.md` if it was used during session

## Rules

- Keep `memory/MEMORY.md` routing table under 150 lines
- Use trajectory format: what, when, why, impact — not just facts
- Don't turn memory files into changelog graveyards
- Each data file owns one domain — don't cross-contaminate
